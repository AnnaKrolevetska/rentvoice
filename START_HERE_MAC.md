# RentVoice — встановлення на Mac у НОВУ папку

Архів `rentvoice-final.zip` містить **увесь** проєкт у папці **`rentvoice-v2`**.
Твоя поточна папка `rentvoice` нічого не втрачає: ми її не замінюємо і не перезаписуємо.
З неї потрібні лише два файли — `.env` (твій ключ) і база даних з бронюваннями —
і їх ми скопіюємо командами в Terminal, а **не** перетягуванням у Finder.

> Нижче вважається, що стара папка — `~/Downloads/rentvoice`. Якщо вона в іншому місці,
> заміни цей шлях у командах.

## 0. Перевір Node.js (один раз)

Відкрий **Terminal** (Cmd+Пробіл → `Terminal` → Enter):

```bash
node -v
```

Потрібно `v20.12` або новіше (краще `v22…`). Якщо команди немає — встанови **Node.js 22 LTS**
з https://nodejs.org, потім закрий і знову відкрий Terminal.

## 1. Зупини старий сервер

У вікні Terminal, де працює RentVoice, натисни **Ctrl+C**.
(Це важливо: так база даних повністю записується на диск перед копіюванням.)

## 2. Розпакуй новий проєкт

1. Завантаж `rentvoice-final.zip` у **Downloads**.
2. Двічі клацни по ньому → з'явиться папка **`rentvoice-v2`** (поруч зі старою `rentvoice`).

## 3. Встанови і перевір НОВИЙ проєкт (ще без твоїх даних)

```bash
cd ~/Downloads/rentvoice-v2
npm install
npm test
```

В кінці `npm test` має бути:

```
# tests 34
# pass 34
# fail 0
```

## 4. Скопіюй свій ключ і базу даних зі старої папки

```bash
cp ~/Downloads/rentvoice/.env ~/Downloads/rentvoice-v2/.env
mkdir -p ~/Downloads/rentvoice-v2/data
cp ~/Downloads/rentvoice/data/rentvoice.db* ~/Downloads/rentvoice-v2/data/
```

- Перша команда копіює `.env` (ключ OpenAI і `APP_TODAY=2026-10-01`).
- Третя копіює базу `rentvoice.db` (і службові файли `-wal`/`-shm`, якщо вони є).
- Нічого не видаляється: стара папка лишається як резервна копія.

Перевір, що бронювання на місці (тільки читання, нічого не змінює):

```bash
npm run db:snapshot
```

Мають бути твої бронювання, наприклад BK-SEED-001 (10–12 Oct) і Camera A 15–17 Oct.

> Якщо `.env` у старій папці немає: `cp .env.example .env`, потім `open -e .env`, встав ключ
> замість `sk-...` (без лапок), збережи. Рядок `APP_TODAY=2026-10-01` не чіпай.

## 5. Запусти

```bash
npm start
```

Відкрий у Chrome **http://localhost:3000** і натисни Cmd+Shift+R (оновлення без кешу).
Унизу таблиці бронювань має бути `Database file: rentvoice.db` і твої бронювання.

Коли переконаєшся, що все працює, стару папку можна залишити як архів або видалити сама —
це твоє рішення, автоматично нічого не видаляється.

## Запис тестових сценаріїв, не чіпаючи твої бронювання

Для відео й доказів використовуй окрему тестову базу:

```bash
npm run test-db:reset       # тестова база = лише тестове бронювання з брифу
npm run start:test-db       # застосунок на data/test-run.db
```

У таблиці буде `Database file: test-run.db`. Покрокові сценарії — у `TEST_SCENARIOS.md`.
Стан бази до/після: `npm run test-db:snapshot`. Повернутися до своєї бази: Ctrl+C і `npm start`.

## Якщо щось пішло не так

| Що бачиш | Що зробити |
|---|---|
| `Cannot GET /` | Подивись у Terminal: сервер напише `Missing UI files in public/`. Розпакуй архів заново в нову папку. |
| `EADDRINUSE` або «port 3000» | Старий сервер ще працює: `lsof -ti :3000 \| xargs kill`, потім `npm start`. |
| `npm install` падає | Встанови Node.js 22 LTS (крок 0) і повтори. |
| `OPENAI_API_KEY is not set` | Перевір `.env` (крок 4), потім Ctrl+C і `npm start`. |
| `No such file` при копіюванні бази | Стара папка в іншому місці або база ще не створювалась — перевір шлях; без бази застосунок створить нову з тестовим бронюванням. |
| Попередження `APP_TODAY is not set` | Додай у `.env` рядок `APP_TODAY=2026-10-01`. |

Кнопка **Reset to seed** і `npm run reset-db -- --yes` видаляють усі бронювання, крім
тестового, але **спершу** зберігають копію бази в `data/backups/`. Самі вони ніколи не
запускаються.
